# 复盘

## 主要难点

最需要分清的是“模型说完成”和“方案已经保存”。模型的结束动作可能早于保存，也可能在保存后才遇到步数上限。程序分别记录任务状态和 saved：没有保存就拒绝 COMPLETED；已经保存但达到上限时，返回 INCOMPLETE，并保留保存结果。续跑只补剩余动作。这个情况在 [进程恢复记录](../examples/packaged/result.json)和 AgentRunnerBoundaryTest 中有验证。

另一个难点是换方案后仍要保留已发生费用。标准方案报价 12，预算只有 10，模型改选精简方案后，已经支付的检索费不能清零。询价结果保留为快照，下一轮决策另外计算当前尚需费用。保存失败后的续跑同样复用检索和脚本，实际记录中的费用由 11 增至 12，见 [续跑结果](../examples/live/extended/save-resume/response.json)。

## 实现中的经验

- 模型选择动作，代码检查预算、时间、依赖和保存条件。不能直接把模型说明当成账目或保存事实。
- 失败记录和成功结果都要保留，恢复时才能判断哪些步骤需要重做。
- 保存方案和任务状态放在一个短事务中，模型请求放在事务外。
- 测试既要检查结果，也要检查过程，例如失败后是否重试、费用是否重复计算、查询次数是否随数据量增长。
