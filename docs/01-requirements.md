# 需求与成功标准

## 用户和目标

运营人员输入活动主题、预算和截止时间，获得约束内的内容任务计划、步骤状态、实际工具结果、费用合计及已保存方案，或明确的未完成原因。

## 范围

实现第 2 题 HTTP API。四个工具为素材检索、成本估算、脚本生成、方案保存；使用合成素材、费用和耗时表。不接真实发布，不包含前端、登录和线上部署。

技术栈为 Java 21、Spring Boot、Spring AI、MyBatis-Plus、MySQL。服务接口位于 service，实现类位于 service.impl；调用方通过构造器注入接口。数据库操作优先使用 MP 服务实现，Mapper 只继承 BaseMapper，不使用 Mapper XML。时间字段使用 `Time` 结尾，SQL 列使用 `_time`；对外时间为带时区的 ISO 8601，数据库 DATETIME 按 UTC 保存。

## 功能验收

| 编号 | 场景 | 成功标准 |
| --- | --- | --- |
| A01 | 正常完成 | 素材、询价、脚本、保存有真实工具结果，保存后才允许完成 |
| A02 | 缺预算或截止时间 | NEEDS_INPUT，明确缺失字段，不猜测输入、不产生费用 |
| A03 | 工具失败 | 错误进入下一轮模型观察，保留成功结果，失败不记成功费用 |
| A04 | 预算超限 | 模型观察不可行报价后选择替代方案；无可行方案则明确未完成及缺口 |
| A05 | 重复执行 | 相同请求复用结果，不增加模型步骤、工具费用或方案记录；变更输入返回 409 |
| A06 | 失败续跑 | 显式续跑只执行剩余步骤，保留成功产物和失败记录 |
| A07 | 截止时间 | 已过期不执行收费工具，预计完成超期不允许保存 |
| A08 | 事务一致性 | 插入方案后注入异常可回滚，保存失败不得虚报成功 |
| A09 | 执行上限 | 达到本轮步数上限返回 INCOMPLETE / STEP_LIMIT，报告实际保存状态 |
| A10 | 数据变化 | 改费用、素材或模型配置后使用新 ID；动作与结果对应新工具观察 |

## 模型决策

至少完成“模型动作 → 工具执行 → 观察 → 下一次模型动作或结束”。每轮只接受合法工具或结束动作。框架不自动代替业务层执行工具，也不自动重复收费动作。预算、截止时间、工具凭证和保存事实由代码校验，模型不能越权修改。

记录步骤、工具参数、返回摘要、后续动作和简短依据，不采集内部思维过程。至少两条真实模型路径体现不同观察后的动作变化。
